# Main Menu UI Resource And Viewport Notes

This document is source-like reverse-engineering documentation, not recovered
original source. Addresses refer to `China2EX_fontfix8.exe` with image base
`0x400000`.

## Main Menu Init

Address range: approximately `0x478eb0` to `0x478ff1`.

```c
void main_menu_init(void)
{
    trace("MainMenu_Init");

    if (!is_some_runtime_mode_active()) {
        switch_game_mode(g_current_game_mode);
    }

    set_view_or_cursor_center(0x200, 0x180);
    select_dirty_or_cursor_mode(10);

    g_view_center_x = 0x200;
    g_view_center_y = 0x180;
    g_previous_frame_time = g_current_frame_time;

    if (g_mainmenu_background) {
        free_background(g_mainmenu_background);
        g_mainmenu_background = NULL;
    }

    g_mainmenu_background = load_tmg_background("MAINMENU", 0);
    load_emg("MENU_ITEM.EMG", &g_menu_item_emg);
    load_xmg("MAINMENU.XMG", &g_mainmenu_xmg);

    if (g_current_game_mode != 1) {
        switch_game_mode(1);
    }

    g_mainmenu_selection = -1;
    clear_mainmenu_button_state_table();
    g_mainmenu_button_state_table[0] = 0;
    g_present_state = 2;
    g_mainmenu_init_time = get_tick_delta();
}
```

## Hard-Coded 1024x768 Baseline

The main menu path is the first confirmed UI initializer that still carries a
1024x768 assumption even after the DirectDraw mode table is patched to
1600x1200:

| Address | Original instruction meaning | Original value | 1600 experiment value |
|---:|---|---:|---:|
| `0x478ee6` | push y center for `0x48b4f0` | `384` | `600` |
| `0x478eeb` | push x center for `0x48b4f0` | `512` | `800` |
| `0x478f1b` | write `0x77b1b4` | `512` | `800` |
| `0x478f25` | write `0x77b1c8` | `384` | `600` |

The experiment is generated by:

```text
python tools\reverse_probe\patch_mainmenu_viewport.py --force
```

and launched with:

```text
start_modtest_1600x1200_menuviewport.bat
```

Expected interpretation:

- If the menu layout or dirty region changes, the main menu is using this
  center/viewport state as part of its 1024x768 lock.
- If the menu remains exactly 1024x768, the remaining cap is likely in the
  background resource dimensions or in the `.TMG` draw path.

Note: the initial batch launcher for this experiment accidentally passed
unsupported `ModernLauncher.ps1` arguments, causing the launcher GUI to open
instead of directly starting the experiment EXE. Retest with the corrected
`start_modtest_1600x1200_menuviewport.bat`.

## Background Draw Routine

`0x4f5ce9` is the common image blit routine used by main menu display paths:

```c
void draw_image(int dst_x, int dst_y, uint16_t *image)
{
    uint16_t width = *image++;
    uint16_t height = *image++;

    Rect clipped = clip(dst_x, dst_y, width, height, g_clip_rect);
    if (clipped.empty) {
        return;
    }

    copy_16bit_pixels_to_backbuffer(clipped, image);
}
```

Important interpretation:

- The draw routine reads dimensions from the decoded image payload.
- It clips against globals such as `0x5cff3a/0x5cff3e/0x5cff42/0x5cff46`.
- It does not appear to hard-code 1024x768 by itself.
- A larger `MAINMENU.TMG` is therefore a valid next experiment, provided the
  `.TMG` loader and resource memory allocations accept it.

## TMG Background Loader

`0x49bec0` opens a background under the `GRAPH` directory with `.TMG` appended.
It reads a 0x80-byte PCX-like header and computes:

- `0x7150e0 = right - left + 1`, width.
- `0x715058 = bottom - top + 1`, height.

For `MAINMENU`, the current resource is `1024x768`, so even a 1600x1200 back
surface can still receive only a 1024x768 painted background unless the loader
and draw routine are taught to scale, tile, center, or consume a larger source.
